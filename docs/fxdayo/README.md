## 二つの実行経路

**専用adapter**は、確認済みの原文SHA、PMX構造、controller等の契約を照合し、ViewerのMetal処理へ接続します。MobFesPenlight_3、MMDayo_SSR、beam、Cracker、ikHolographicなどが対象です。ファイル名や拡張子を変えるだけで新しいエフェクトに対応する仕組みではありません。既知原文との一致を示す `exactSource` と、原版との画像同値も別です。Blue Palace SSRは専用の近似adapterとして扱います。

**限定原文runtime**は「この原文を試す」を明示して使います。同梱のJsonnet→DXC→SPIRV-Cross→Metalという経路でコンパイルし、型、reflection、資源予算、色段階、実行profileを検査します。Homebrewは前提にしません。任意のWindows MME `.fx`／HLSLを一般実行する機能ではありません。

| 原文profile | 現在の扱い |
|---|---|
| `dayo130.hdr-scene.v1`／`dayo130.hdr-color.v1` | 初期の限定契約を保持 |
| `dayo130.postprocess.v2`／`dayo130.color.v2` | 共通定義・pass macro、対応するBORDER／UNORM、self bool／int、2D／3D texture、mip・clear／copy等の拡張契約 |
| `dayo130.postprocess.v3`／`dayo130.color.v3` | v2の範囲に順序metadataの `stage`／`subHintOrder` を追加。v0.57.42以降 |

旧v1／v2を開いたときに、v3へ自動移行して順序を変更することはありません。色処理専用profileではFXAAとの明示的な併用条件があります。HDR、原文tone mapper、表示linearを分け、tone mappingの担当と順序を検査します。

v0.56.46以降はボーンcontrollerとUUIDで指定する別個体controllerにも対応し、モーフ・ボーン・時刻を同じ評価世代から供給します。旧資料の「骨・外部個体は未対応」は当時の制約です。外部画像の原文依存保存は、対応する不透明8bit PNG／BMPとsRGB契約の範囲です。HQの環境HDR読込など、別機能の対応を原文runtimeの汎用画像対応へ広げないでください。

## 推奨順は明示操作で適用

v3では原文の順序metadataを保持します。`stage` は既知名、または非負Int32の数字を表す文字列です。既知名の基準値は次のとおりです。

| stage | 基準値 |
|---|---:|
| `first` | 0 |
| `scene`（省略・空文字の既定） | 1000 |
| `camera` | 2000 |
| `tonemapping` | 3000 |
| `composition` | 4000 |
| `last` | 10000 |

`subHintOrder` は0〜99の整数で、省略時は50です。比較には基準値との和を使い、整数の範囲外や不正な型を拒否します。metadataは原文SHAとpackageの識別情報へ結び付けて保持します。

利用者が「推奨順」を適用したときだけ並べ替えます。ロック、非postprocess、metadata不明・不正の要素を固定境界とし、その間の連続区間だけを並べ替えます。同順位は元の順序を保ち、色段階・HQ構成・native／原文の混在条件を再検査します。読込や再生開始時の自動ソートではありません。Undo、project保存・再読込、動画出力も確定した順序に従います。順序metadataの保存はproject reader44以降の機能です。

## Blue Palace床反射の世代

床形状のprofileと原文実行profileは別の版体系です。専用SSRは一つの可視controllerを使い、native live描画はToonShader HQを条件とします。

| 世代 | 反射とcontrollerの範囲 |
|---|---|
| v1〜v4 | 確認済みの床形状ごとに画面内の色・深度を探索。missは反射なしで、画面外の補完はない。使わないMirrorScene描画は省略 |
| v5 | v4の床形状に、画面内SSRと床高0／2／4／6の鏡像補完を組み合わせる。trace有効性をR8画像で保持し、深度・床段差・自己反射を保護 |
| v6 | 別の原文SHAと専用controller契約でRoughnessを追加。同じ床・深度の反射範囲でぼかし、0ではv5相当。旧controllerの改名では移行できない |

v5／v6の鏡像は主画面と共通のStandard／Toon／HQ材質計算を使い、Holographic、Rhinestone、PBRの入力も反映します。反射合成では元画像のalphaを保持し、主画面のAA・DoF・Bloomは合成後に適用します。中心ボーンによる平行移動と床の切取りを扱う限定profileであり、任意のステージ回転・拡大縮小や汎用レイトレーシングの保証ではありません。

v6を保持するprojectにはreader46、エフェクト割り当てJSONにはv2が必要です。旧v1〜v5は元の原文・契約を保持します。この資料更新で原文やcontrollerの配布物を新たに同梱したわけではありません。

SSRのCPU準備はv0.57.44では実験的な既定OFFでしたが、v0.58.1では既定ONです。同一build562の比較はCPU encodeを42.9%短縮し、実表示FPSを3.5%増やした一方、GPU p95が21.4%悪化し、正式性能は未受入です。旧資料の既定値と局所的な短縮結果を、現在の全体性能の保証として読まないでください。

## 時間・保存・失敗時の境界

FrameTimeはVMDフレーム÷30秒を使い、停止中は時間依存の効果も停止します。RealTimeは対応する効果だけを停止中も進め、VMD、カメラ、音声、物理の時計は進めません。再生中はフレーム時刻にそろえ、出力は開始時に固定した入力から決定論的に評価します。

v0.58.1以降のエフェクト割り当てJSONは、適用済みの材質・controller・原文等をPMX単位またはproject単位で移せます。PMXのSHAと材質表を照合し、同一素材の複数個体は対応先を明示します。project単位はHQ基底値と登録済みキーも保持します。新しいHQ画質設定や床反射v6を含む場合は割り当て形式v2が必要です。保存できた設定でも、未対応の混在を実行できるようにはなりません。

原文の再読込ではPMX・物理・未登録編集を保ち、新候補のGPU成功と実表示を確認するまで旧受理版を使います。v0.57.44以降、世代変更で古くなった候補は、通常シーンの実表示・状態確定と旧原文のGPU利用終了を確認して、一世代につき一度だけ自動再試行します。終端障害・隔離状態を自動解除したり、未表示の候補を採用したりする処理ではありません。

GPU device障害は通常の候補失敗と別です。描画・背景GPU処理・MetalFX生成・動画出力を再起動まで止め、保存は維持します。resize、AA変更、古い成功通知で解除しません。v0.58.4の動画入りproject保存・動画本体を除く自動復旧については[技術ガイドの保存節](../../VvfM_Technical_Note.md#2-5-手動保存と自動保存の復旧範囲)を参照してください。

## 対応範囲と検証の読み方

任意の端数dispatch、共有Fog／Fluid simulation、nativeと原文の全面混在には対応したと説明できません。beamはcollision=0の専用契約で、透明ProRes出力を拒否します。並べ替えやcontrollerを隠す操作だけで、残る依存関係の不適合が解消するわけでもありません。

v0.58.1の組合せ記録では、5モデル・原文3種・FrameTime等の限定条件で編集・保存・復旧・出力を確認しました。一方、nativeと原文を混在させた7モデル構成は拒否されています。成功した構成の結果を、失敗した構成の対応宣言へ広げないでください。

v0.58.4の直列全Swift試験は3,712通過・178 skip・issue 0という開発元記録ですが、外部入力不足による早期return 7件を実素材の通過には数えません。構造schema、解析、コンパイル、GPU実行、正しい世代の実表示、原版との画像同値、正式性能、600秒耐久はそれぞれ別の確認です。版別の残課題は[技術ガイド付録B](../../VvfM_Technical_Note.md#付録b-資料と根拠の要点)にまとめました。今回の文書更新ではアプリのビルド・テスト・GUI・性能測定を再実施していません。
